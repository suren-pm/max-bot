## What's in the code today (DO NOT roll this back — it's correct)

`src/bot/joinMeet.ts` on `main` has the full working browser config. Key pieces:

1. **playwright-extra + puppeteer-extra-plugin-stealth** — wraps Playwright's Chromium with ~20 fingerprint evasions
2. **Two specific evasions disabled:** `iframe.contentWindow` and `media.codecs`. These two are specifically detected by Google Meet — disabling them is the documented fix from [puppeteer-extra discussion #907](https://github.com/berstend/puppeteer-extra/discussions/907). This change alone moved the bot past the edge-level workspace.google.com redirect.
3. **launchPersistentContext** (not launch + newContext) — mirrors upstream MBaaS `src/browser/browser.ts` exactly
4. **Full WebRTC + audio + cert launch args** copied from upstream MBaaS
5. **macOS Chrome User-Agent + locale en-US** in newContext
6. **navigator.webdriver override + navigator.platform="MacIntel"** via context.addInitScript
7. **bypassCSP: true** at context level, **permissions: ['microphone', 'camera']** at launch
8. **Browser warm-up:** navigate to google.com first, dwell 2.5s with mouse moves + scroll, then navigate to Meet
9. **waitUntil: 'domcontentloaded'** (not networkidle — Meet's WebRTC keeps network busy forever)
10. **fillBotName + clickJoinCta are best-effort** (don't throw on failure)

The standalone test script `test-meet-local.js` at repo root applies the same config minus the audio pipeline. Run it on any machine:

```bash
cd ~/Documents/Claude/max-bot
npx playwright install chromium
node test-meet-local.js https://meet.google.com/YOUR-ROOM-CODE
```

A Chromium window opens visibly. From a residential IP, you'll see the Meet pre-join screen. From a Railway/data-center IP, you'll see the "You can't join" page.

## What's left — the actual open question

Pick one of these paths. Each has trade-offs. None is "obviously right" without further evidence:

### Path A — Workspace OAuth (likely correct per original design doc)
Create a real Google Workspace account (e.g. `max@everperform.com`), run OAuth consent flow once interactively, store refresh token as Railway env var, inject auth cookies into the Chromium context before navigating to Meet. Authenticated guests bypass virtually all anti-bot checks. Cost: ~$7/mo per Workspace seat + half-day of code. **Strongest single fix.**

### Path B — Migrate max-bot to a non-Railway host, then re-test
Multiple candidates, all datacenter ASNs:
- **AWS Lightsail / EC2 (AS16509)** — AWS IPs broadly trusted by Google. Most likely to actually help.
- **Fly.io (AS54113)** — different ASN; community results mixed.
- **DigitalOcean (AS14061)** — different ASN; community results mixed.
- ~~Hetzner (AS24940)~~ — **I called this residential-looking earlier; it isn't.** Documented poor Google reputation. Probably worse than Railway. Don't pick this.

If you go Path B, verify with `/diag/egress` after deploy and only commit to the migration if `/diag/page` shows real Meet pre-join (not workspace redirect).

### Path C — Hybrid: residential proxy in front of Chromium outbound
Keep max-bot on Railway, route Chromium's outbound traffic through a residential proxy (Bright Data, Oxylabs, Soax). Bypasses ASN entirely. Costs: ~$0.50–$5/GB depending on provider. Half-day of code.

### Recommended next step (my opinion, treat as input not gospel)
Before any infra spend: **test Path A locally first.** OAuth-into-Chrome on Suren's Mac, navigate to Meet, see if it works without stealth at all. If yes → OAuth is the answer and you don't need to migrate hosts. If no → it's deeper, and host migration is the only remaining lever.

## Lessons locked from this session

1. **Always web-search a specific error string before theorizing.** The puppeteer-extra discussion #907 with the iframe.contentWindow + media.codecs fix surfaced in ONE search. I theorized for 2 hours before searching.
2. **A/B isolation before code changes.** When something "was working" stopped working, run the local-vs-remote test FIRST to know which side the regression is on. I burned ~4 hours patching code before doing the Mac-local test that closed the diagnosis.
3. **Memory must be in the workspace folder, never per-space dir.** Session 26 already locked this rule. I repeated the mistake by writing to `~/Library/Application Support/Claude/local-agent-mode-sessions/.../spaces/.../memory/` — invisible to any new session. Don't repeat. This file at `~/Documents/Claude/max-bot/HANDOFF_2026-06-08.md` is the durable record.
4. **Don't state confidence you haven't earned.** I called Hetzner "residential-looking" with no basis. AS24940 is datacenter with documented poor Google reputation. If you don't know an ASN's reputation, web-search the AS number before recommending.
